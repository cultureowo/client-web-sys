# Study Planner · Лабораторні №8–9

Навчальний планувальник: Vite + React 19 + TypeScript, SCSS + BEM. Потрібен Node.js **22.22 або новіший**; перевірено на 24.13.0.

## Запуск і перевірка

```sh
npm ci
npm run dev
npm run lint
npm test
npm run build
npm run preview
```

У PowerShell із забороненими скриптами використовуйте `npm.cmd`. Тести використовують вбудований test runner Node.js і підтримку TypeScript.

## Можливості

- Створення, редагування, валідація та перемикання виконання завдань.
- Категорія, колір, три пріоритети; пошук, фільтри й сортування.
- Статистика й окремі повідомлення для порожнього списку та порожнього результату пошуку/фільтра.
- Видалення з 5-секундним таймером, прогресом і кнопкою «Скасувати»; завдання залишається у списку з позначкою «Буде видалено».
- Масове очищення виконаних із Undo для всієї групи. Одночасно підтримується одна операція: одиночна або групова.
- «Скинути дані» відновлює початкові завдання та скасовує pending deletion.
- Власний Toast: create/edit/delete/errors, автоматичне закриття звичайних повідомлень через 4 секунди.
- Збереження завдань та активного фільтра в localStorage.
- Заголовок вкладки із кількістю невиконаних завдань.
- Адаптивний інтерфейс, світла/темна тема. Тема, пошук і сортування діють у межах сесії.

## Структура та стан

```text
src/
  components/                # компоненти та їхні .scss
    TaskForm.tsx             # створення/редагування, локальні поля
    TaskItem.tsx             # один task через props, дії через Context
    TaskList.tsx             # список та порожні стани
    TaskStats.tsx            # похідна статистика
    TaskFilters.tsx          # фільтрація, пошук, сортування
    Toast.tsx                # звичайні та Undo-повідомлення
  context/TaskContext.ts     # тип API і createContext
  context/TaskProvider.tsx   # reducer, операції та effects
  reducers/taskReducer.ts    # чисті переходи стану
  hooks/useTaskContext.ts    # доступ до Context із перевіркою Provider
  hooks/useLocalStorage.ts   # generic hook для фільтра, безпечне читання
  data/initialTasks.ts
  types/task.ts
  styles/app.scss            # глобальні базові стилі
  App.tsx                    # композиція інтерфейсу
  App.scss                   # BEM-блоки сторінки
  main.tsx                   # StrictMode → TaskProvider → App
tests/                       # reducer та читання сховища
```

`useReducer` — єдине джерело правди для tasks. Actions: `add`, `toggle`, `update`, `requestDelete`, `confirmDelete`, `undoDelete`, `clearCompleted`, `reset`. Reducer не звертається до DOM, таймерів чи localStorage. UUID і час операції створюються у Provider. Статистика й видимий список обчислюються під час render без effects або окремих лічильників state.

Ключі сховища: `study-planner.tasks.v1`, `study-planner.filter.v1`. Lazy initializer читає завдання; Effect записує оновлений масив. Пошкоджений JSON, неправильна структура й повторні ID замінюються початковим списком; збережений порожній масив залишається порожнім. Недоступне сховище не руйнує застосунок. Помилка запису завдань показується у Toast та постійному повідомленні, помилка запису фільтра — у повідомленні інтерфейсу.

Pending deletion існує лише в сесії. До підтвердження завдання залишається в tasks і localStorage, тому перезавантаження скасовує незавершене видалення. Effect запускає таймер та повертає `clearTimeout` у cleanup. Undo і reset очищають pending; токен захищає від застарілого підтвердження. Звичайний Toast не приховує кнопку Undo.

У двох effects локально вимкнено `react-hooks/set-state-in-effect` із поясненням: state повідомлення відображає результат синхронізації із зовнішнім сховищем. Інші перевірки ESLint залишені активними. Синхронізація між вкладками не реалізована.

## Захист

1. Додати завдання й показати Toast та статистику.
2. Відредагувати поля, зберегти зміни.
3. Запустити видалення, показати стан очікування, прогрес і Undo.
4. Повторити видалення й дочекатися завершення 5 секунд.
5. Створити завдання, обрати фільтр, перезавантажити сторінку: дані відновлюються.
6. Показати Provider у `main.tsx`, reducer, effects із cleanup, обидва custom hooks і споживача Context у `TaskItem`.
7. Продемонструвати масове Undo та скидання даних.
